# SPEC — pair-watcher v1

Source: a wayfinder map with tickets `01–23`, research and prototypes (answers + amendments; an amendment overrides its ticket). The map, tickets and research stay in the maintainer's private checkout; prototypes ship in `.scratch/pair-watcher/prototypes/`. This file is the contract and is complete on its own; where the private trail disagrees, this file wins. Vocabulary = `CONTEXT.md` (Worker, Watcher, Focus, Companion mode, Swarm, Wake, Blind, Commentary, Concern, Approach-level, Challenge, Debate, Ruling, Standing ruling, Escalation); capitalised term means exactly its glossary entry. Parenthesis after a §V heading = source ticket files.

## §G

G1|Watcher follows one Worker (Claude Code, Codex, pi) and speaks Navigator-style: Commentary of evaluative Concerns to the human in a side pane; Challenge + bounded Debate into the Worker only for approach-level objections; Escalation (only notifying speech) for unresolved Debates and Worker-blocked questions.
G2|Companion mode default (one Watcher, all Focuses); Swarm opt-in (one Watcher per Focus, shared Concern list + one Challenge slot).
G3|Metrics mechanism: one session event log → ratio headlines (H1–H4), silent-session audit for recall, `replay --variant` as test for prompt/Focus/model changes.
G4|Host-independent core (hooks + transcript tailers + own pane + OS notifier); Herdr optional front-end.

## §C

C1|Principle **earn the interruption**: speak only when it would change what happens next; silence = success; no quota, no volume metric; before any Challenge/Escalation ask "would the human want the Worker's flow broken for this?"; once the human ruled, drop it for good. Human always has final say.
C2|Watcher observes + speaks only: never edits repo, never writes into Worker repo (incl `.git`), never blocks/pauses/gates Worker, never holds `Stop` while thinking, never steers mid-turn, never types into a prompt box, never answers for the human.
C3|Worker untouched by default: launcher uses per-session flags only (Claude `--settings`+`--plugin-dir`, Codex `-c hooks.*`, pi `-e`); user config edited only by opt-in `install`.
C4|Core works without Herdr; Herdr used only for pane split, `notification show`, status (Codex blocked confirm, observe-only wake source).
C5|Harnesses: Claude Code, Codex, pi. Last-tested: Claude Code 2.1.289, Codex 0.160.0, pi 1.0.2; minimum versions TBD in T16 (compat table). Platforms macOS + Linux.
C6|Runtime: Rust core, one `pair-watcher` binary (Watcher, CLI, hook helper, MCP read tools). Adapters TS/JS (Claude mod, pi extension), embedded in binary, lock-step versions.
C7|extra-eyes has no licence: reuse ideas only, no code, no prompt text.
C8|Data local under `~/.pair-watcher/` mode 0700. Egress only: wake input to configured model provider; opt-in hosted pre-filter (labelled); opt-in weekly aggregate telemetry (counts/ratios only, never text/paths/repo names/prompts); manual `report --export`.
C9|Cloned repo config = untrusted input: may tighten, never raise spend, enable egress, or silence a Watcher.
C10|pi with Claude or Gemini subscription login as Watcher backend refused (terms). Codex launch never uses `--dangerously-bypass-hook-trust`.
C11|Out of scope: fleet watching (many Workers), Watchers editing repo, gatekeeping, agent teams as host, API proxy host, tmux/PTY as primary host, agent-comms except opt-in Debate transport (not v1).

## §I

I1|CLI|`pair-watcher run [-c key=value]… [--mode companion|swarm] [--ceiling <usd>] [--focus <name>]… -- <claude|codex|pi> <args…>`; `attach <session>`; `pane [--session <id>]`; `hook <event>`; `mcp`; `install|uninstall claude|codex|pi|all`; `auth`; `models update [--yes]|rollback`; `doctor`; `config show [--origin]`; `focus approve <name>`; `mute <focus>` / `nochallenge` / `pause`; `rule <id> watcher|worker|dismiss` / `undo` / `keep`; `rulings list|rm`; `report [--export] [--explicit-only]`; `prefilter fit [--target <recall>]` (writes `prefilter/thresholds.json`); `replay --variant <prompt|focus|model> <wake-set>`; `audit [--yes] [--max-usd 5] [--sample 20] [--model <m>] [--resume]`; `telemetry on|off|preview`; `prune`. Session-scoped commands (`rule`, `undo`, `keep`, `mute`, `nochallenge`, `pause`, `focus approve`) take `--session <id>`; default = the only live session in the current repo, else refuse and list sessions.

I3|Repo files|`<repo>/.pair-watcher/config.toml` (filtered, V79–V80), `<repo>/.pair-watcher/focus/<name>.md` (needs approval). Read only; never written.
I4|Mailbox|`sessions/<id>/`: `events.jsonl` (hook appends, fail-silent), `outbox.jsonl` (Challenges/Rulings, two-phase claim/ack), Commentary/event log the pane tails, per-wake record files (zstd), tree-snapshot object store. Every record carries schema version; record types defined in Rust + TS.
I5|Hooks (wake)|Claude: `Stop`, `PermissionRequest` (incl `AskUserQuestion`; payload `tool_input`). All via `~/.pair-watcher/bin/pw-hook <event>` (sh shim → `pair-watcher hook`, else exit 0). Env guard var set for Watcher subprocesses; hooks no-op under it.
I6|Tailers|Claude JSONL transcript (`transcript_path`), Codex rollout + guardian sibling rollout (`session_meta.parent_thread_id` = Worker session id, `source.subagent.other: "guardian"`; events `task_started`, `task_complete` `last_agent_message.outcome`), pi session file. Use arrival time, not entry timestamps.
I7|Delivery routes|Claude: `Stop` hook block (`decision: block`, reason = Challenge text; `stop_hook_active` guard) → mod `$.prompt.submit` → next `Stop`. Codex: `codex queue --thread <id> --message <text>` after `Stop`. pi: `sendUserMessage(text, {deliverAs:"followUp"})`.
I8|Claude mod|JS module in `adapters/<v>/claude/`: idle delivery (`$.prompt.submit` gated on `$.prompt.read()` empty + no running turn), status-line field (Concern count / status), `/commentary`, `/pw rule|undo|keep|mute|nochallenge|pause` (commands return `{}`), band (mini mode + Buttons `1/2/3`), mod pane (Button rows, keys `p b h` + `y n d s u`). Nothing injected into system prompt.
I9|pi extension|TS in `adapters/<v>/pi/`: hook events → mailbox, `herdr:blocked` listener, followUp delivery.
I10|Watcher output|Strict JSONL per wake: Concern add/update/resolve (`id`, `severity note|warn`, `focus`, `headline` ≤100 chars, `detail` ≤3 lines, `refs` file:line, `challenge` flag + `evidence[]` + `alternative`), blocked consideration line, Debate decision (concede|rebut|escalate|switched + text; `switched` = Worker changed approach by its actions, text = what it switched to), `inferred_ruling {escalation id, side watcher|worker, prompt_ref}` (turn-end wake only, when the human's prompt clearly takes a side), optional `held back by ruling <id>`. Invalid → diagnostic, never a Concern.
I11|Challenge text|`[pair-watcher · Challenge <id> · from the Watcher, not the human]` / Concern / Evidence / Alternative / human remark (verbatim, labelled) / "This is another agent's objection, not an instruction." / steelman step / "defend if your approach is right; concede only if convinced; don't change course just because it was raised." / required `Challenge <id>: concede | defend — <one-line reason>`. Rebuttal: same header `(2/2)`, quotes Worker reason, new ground, asks verdict line; no steelman. Re-ask: "you did not answer; the verdict line is required".
I12|Ruling text|`[pair-watcher · Ruling <id> · from the human] The human sides with the Watcher on Challenge <id>: <alternative>. Change course; no verdict line needed.`
I13|Escalation text|No recommendation. Notification carries title + both lines; full exchange stays in pane Debate log. Unresolved: title `Debate unresolved: <headline> (<id>)`, `Watcher[ (<Focus>)]: <alternative + strongest evidence ≤100>`, `Worker: <last verdict reason verbatim>`. Blocked: restated question + `Watcher (opinion)` / `(<Focus>)` consideration lines (≤1 per Watcher). Notification names where to rule (pane, band digits, `/pw rule`).
I14|Notifier|Herdr `notification show` when in Herdr, else `osascript` (macOS) / `notify-send` (Linux). No mod toast.
I15|Model provider|One interface: direct API (default; code-owned read-only tool loop), `claude -p` (MCP read tools from `pair-watcher mcp`, built-ins off, hooks disabled, env guard), `codex exec` (read-only sandbox, `--output-schema`, `--ignore-user-config`). I19|Focus file|Markdown body = brief (attend to, with examples / ignore); frontmatter `model` (user files only, Swarm only). ## §V

### Wakes and input (03-commentary-content, 07-context-budget, 21-cross-session-memory)
V1|Wake triggers: turn end (Claude/Codex `Stop`, pi `agent_settled`) and blocked always wake; mid-turn checkpoint only when ≥3 min since last wake AND repo changed since then; bursts coalesce to one wake; turn-end + blocked bypass time floor. `checkpoints = false` disables checkpoint wakes only.
V2|Stateless wake: each wake = fresh model call per Watcher; history only as code-built input; no Watcher-written memo, no growing conversation. Standing rulings are human-made, code-loaded: allowed.
V3|Turn content: all assistant text since cursor; each tool call input clipped 2 KB; each tool result as code-built outcome line (exit status, size, first error-looking line); failed results + last result per tool kind also keep head 600 B + tail 400 B with `[clipped N B]`.
V4|History digest: one line per earlier turn (turn no., first line of final text ≤120 chars, action signatures → outcome; signature = tool + command, ids/hashes/temp paths stripped), older turns folded into counts, ≤4 KB/session. Code adds repeat hints (`hint: signature "<sig>" seen N× in last N turns`); hint is input only, Watcher decides.
V5|Diff: since last wake, ≤8 KB (hunks of files the turn touched first, rest as stat lines) + session `--stat` ≤2 KB. Baselines = tree snapshots incl untracked files (session start, each wake) in object store under mailbox. Diff size logged per wake record.
V6|Task section: all human prompts + answers to blocked questions, each ≤1.5 KB, ≈6 KB total; overflow keeps first + latest 3 full, middle folded to first line. Repo instruction files listed by path, read by tool on demand.
V7|Section caps (fixed): prompt + Focus briefs 6 K; human prompts 6 K; Concern list 8 K (all Focuses; open full, dismissed/resolved as id + headline, oldest resolved dropped first); open Debate 4 K; digest + hints 4 K; Standing rulings 2 K (never trimmed); turn content 16 K (outcome lines kept; clipped bodies dropped oldest-first, then assistant text middle-clipped); diff + stat 10 K. Only turn content borrows unused space, up to 24 K; lenders = shared sections only (prompt + briefs never lend, so V9 holds in Swarm). Past spec'd trims: turn content cuts tool call inputs to first line ≤200 B oldest-first, then folds oldest outcome lines into `[N earlier calls: ok A, failed B]`; Concern list collapses oldest open to id + headline, then drops oldest dismissed. Total ≈56 K; long session never grows it.
V8|Tools: read-only, ≤6 calls and ≤24 KB read per wake (separate from input), then output forced. Tools back evidence; not for hunting.
V9|Focus never narrows input or wakes: every Watcher gets identical input + wakes; only addition = its Focus brief.
V10|Cursor per transcript: last entry id + byte offset (id re-anchors after rewind/compaction/resume), hook inbox offset, last diff snapshot, digest state. Committed per Focus: two-phase, a Focus's wake reads under its pending cursor, committed only after arbiter accepts that Focus's output. A failing Focus never stalls or drops coverage of the others; its held slice is replayed for it alone (input identical across Focuses whenever all are current).
V11|Blocked wake: slim, no tools, one call: blocked payload ≤2 K + human prompts + open Concerns + digest + rulings (≈22 K). Human answers first → Escalation dropped (stale).

### Commentary and Concerns (03-commentary-content, 04-challenge-bar, 06-swarm-coordination)
V12|Commentary evaluates only (risk, missed case, contradiction with task, better alternative, unverified claim); no narration, no praise; silence default. Never notifies.
V13|Per wake a Watcher may only: add new, update own id with new evidence, resolve own (fixed / no longer applies / duplicate of <id>). Re-raise without new evidence → dropped. Dismissed Concern never reopens; only a distinct one may be raised. No auto-expiry; session end closes all (Standing rulings excepted, V78).
V14|≤3 new-or-updated Concerns per wake per Worker (resolutions free); arbiter fills in order challenge-flagged, `warn`, `note`, round-robin across Watchers by each Watcher's ranking. Trimmed = never shown → later raise not a repeat.
V15|Severity `note|warn` affects pane order + `escalate_unresolved` gate only.

### Challenge (04-challenge-bar, 08-watcher-model)
V16|Auto-Challenge requires all: approach-level (redo test: if right, done/planned work must be redone or thrown away, not patched), concrete evidence, named alternative direction. Unproductive repetition (same action signature, no new outcome) qualifies; alternative = stop or change strategy.
V17|Evidence is code-verified: every cited item (file:line excerpt, command + output, transcript entry, repeat hint) must exist verbatim in snapshot/transcript/digest. Unverifiable → stays Concern, logged `challenge-ready unverifiable` with failing items.
V18|Challenge = existing Concern sent on; one list, one lifecycle; pane shows "challenged" linked to Debate.
V19|One open Challenge per Worker across all Watchers. Other challenge-ready Concerns wait (no queue), re-checked first wake after Debate ends; oldest Concern wins the slot; no Focus priority; severity does not pick. Winner's evidence re-verified (V17) vs current wake's snapshot/transcript/History before queue; fail → `challenge-ready-unverifiable`, stays Concern until owner updates it; next oldest on a later wake.
V20|Human promotion (`P` standalone, `p` mod pane): any open Concern, no bar, optional one-line remark delivered verbatim labelled as human's. Refused while a Challenge is open (ticker names it). Dismissed Concern cannot be promoted.
V21|Stale check: turn-end wake runs before delivery; if it resolves/updates the Concern, Challenge dropped, one ticker line, nothing reaches Worker. Same for replayed wakes' Challenges.
V22|≤1 auto-Challenge per Concern ever; afterwards only human promotion.
V23|`auto_challenge = false` or pane `a`: approach-level Concerns stay Concerns; promotion still works.
V24|New auto-Challenge admitted only if budget reserve covers its whole Debate.

### Delivery (09-choose-host, 10-live-herdr-check, 13-live-idle-delivery)
V25|Never delivered as steer, never mid-tool, never typed into a prompt box. Herdr `agent prompt` and tmux `send-keys` never used for delivery.
V26|Claude chain: Challenge ready before `Stop` → carried by `Stop` block; else mod `$.prompt.submit` only when `$.prompt.read()` empty and no turn running (held otherwise); else next `Stop`; pane `pending: Worker idle` / `pending: human draft in prompt`. No mod → straight to next `Stop`.
V27|Codex: `codex queue` called after `Stop`. pi: `sendUserMessage` `deliverAs:"followUp"`.
V28|`outbox.jsonl` delivery exactly-once via two-phase claim/ack per Worker session; stale-checked at claim.
V29|Observe-only session (no hooks): Herdr status for wake/status only; Challenges stay pending in pane, never delivered.

### Debate (05-debate-protocol, 06-swarm-coordination, 22-human-ruling)
V30|Verdict detection: last line in turn's final assistant text matching `Challenge <id>:` (other ids ignored). Actions override words: "defend" + switch of approach = worker concedes; "concede" + carrying on = `conceded` until Watcher observes fix.
V31|≤2 exchanges. Exchange 1 = Challenge + verdict. On defence, Watcher rebuts only with new ground answering stated reason; else concedes or escalates at once. After second defence Watcher has last word: concede or escalate, never a third message.
V32|Watcher concedes when defence refutes evidence or names a missed constraint (task text, repo fact, human instruction verified in transcript); never argues against the human. Escalates only on real trade-off.
V33|No verdict line + actions don't settle → exchange 1 "no answer"; exchange 2 = re-ask; still nothing → unresolved.
V34|Human prompt mid-Debate goes first; pending rebuttal/re-ask waits for next idle, stale-checked. Human turn = evidence only: approach switch = worker concedes; Concern no longer applies → `withdrawn`. Never counts as "no answer", never a ruling. Human turn while the Worker's reply is still awaited (reply interrupted or pre-empted, no verdict line) → `withdrawn — human went first` (not adjudicated, Concern stays open) unless owner judges `switched`; a pending rebuttal/re-ask still waits.
V35|Outcomes: worker concedes (Concern stays open `conceded`, resolves only on observed fix) | watcher concedes (Concern resolved) | unresolved (Concern stays open tagged `escalated` or `unresolved-quiet`; human dismisses or leaves it) | withdrawn (Concern no longer applies / human went first V34 / session end / budget: `withdrawn — budget, not adjudicated`) | human sided with Watcher | human sided with Worker.
V36|Unresolved → Escalation (notify) only if Concern severity ≥ `escalate_unresolved` (`warn` default; `note` all; `off` never); below → `unresolved-quiet`, ticker "unresolved, not escalated", no notify.
V37|Close-out logged in pane only; nothing sent back to Worker, except explicit human side-with-Watcher Ruling (V74).
V38|Worker blocked mid-Debate: Debate waits; blocked Escalation goes out.
V39|Swarm: owner Watcher of the challenged Concern argues whole Debate; others cannot join; new ground from another Focus = their own Concern awaiting slot.
V100|Debate closes on owner judgment too: `switched` = worker concedes (overrides "defend", settles "no answer", human turn); challenged Concern closed mid-Debate: owner `resolve fixed` = worker concedes, `resolve no-longer-applies|duplicate` or human dismiss = withdrawn. Owed decision missing or not allowed (`rebut` after second defence or after no answer; `escalate` before the re-ask) → Watcher concedes, logged `defaulted` (silence earns no interruption, C1); slot never held by a silent owner.

### Escalation and notification (03-commentary-content, 05-debate-protocol, 06-swarm-coordination, 20-fail-open)
V40|Exactly one notification per Escalation. Blocked = Escalation: arbiter takes question from blocked event; each Watcher ≤1 labelled consideration line or silence; lines in Focus order; never answers for the human.
V41|Only other notification: first BLIND of a session (sent by supervisor, or pane when supervisor gone; both check log for earlier `blind notified`). Commentary, PAUSED, `paused (you)`, lagging, ladder steps, config problems, repo Focus approval never notify.
V42|Failed blocked wake → no bare notification; ticker `blocked: considerations unavailable`.

### Swarm (06-swarm-coordination, 20-fail-open, research/spec-process-model-brainstorm)
V43|One Watcher process per Worker: one async task per Focus per wake (all run in parallel) + plain-code arbiter (no model) in the same process, sole writer of Concern list, ids, cap, Challenge slot, cursor commits and event log. No per-Focus processes; supervisor holds no Watcher logic. Child-process isolation per Focus deferred until `watcher` crash metrics show OOM/abort. Companion = Swarm of one, same code path; Companion gets every enabled brief. Human surfaces (pane, mod, band, `/pw`, CLI) append only human facts: `human` dismiss/promote(+remark)/helpful/mute/nochallenge/ruling remembered, `shown`, `status` +$5 / user pause/resume, explicit `ruled` (y/n/d), `ruling undone` (u); `human promote` = request, arbiter answers `challenge queued` or `promotion refused` (V19, V20); arbiter answers `ruled` / `ruling undone` with `debate end`, Ruling queue/withdraw, `debate reopened` (V73–V75); folds read facts at once; slot, ids, outbox, `concern` events stay arbiter-only. Inferred `ruled` = arbiter.
V44|Each Watcher sees all open + dismissed Concerns with owner Focus; touches only its own; may not add a repeat of another's; same-wake duplicate → newer owner resolves `duplicate of <id>` next wake.
V45|Swarm = one Watcher per enabled Focus. Per-Focus model override from user Focus files only; unset inherits default `model`.

### Model and budget (08-watcher-model, 20-fail-open, 23-config-surface)
V46|`model = auto`: mid-tier cross-vendor among configured backends — Claude Worker → gpt-6.1-sol; Codex/OpenAI Worker → Sonnet 5.5; other → whichever differs from Worker provider (from transcript); one vendor configured → its mid-tier + pane note `same vendor as Worker`. Capability outranks vendor. One model per Watcher for all its wakes and Debate turns, except a `fallback_model` switch (V51).
V47|Ceiling: API-equivalent USD per Worker session, all Watchers + fallback combined, tokens × price table; subscription backends counted at same rate. Unpriced model refuses to start.
V48|Ladder (constants): 10% reserve for blocked wakes + finishing open Debate; 60% → checkpoints off (`thinned`); 75% → Swarm collapses to Companion on default model; 90% → normal wakes stop; 100% → all model calls stop (`paused`). Tools + evidence rule unchanged at every step.
V49|Status always visible: `watching` / `thinned` / `lagging` / `paused $x/$y` / `PAUSED (you)` / `BLIND`; pane only (except V41).
V50|`$`/`b` adds $5, resumes: replay preserved failure backlog in slices, then one merged catch-up wake (cumulative diff + digest) disclosing omitted activity (`merge-omitted`).
V51|`fallback_model` opt-in, labelled: Key failure → switch for session (after `pair-watcher auth`, switch back via pane `F` / `/pw primary` / `pair-watcher primary`); Service failure → switch after first failed wake, probe primary ≤1×/15 min (one attempt, no retries); never for Slice; applies from next wake; same ceiling. No automatic switch to subscription backend.
V52|Subscription backends opt-in; pane `shares Worker quota, budgets approximate`.

### Pre-filter (18-prefilter-survey, 14-packaging, 23-config-surface)
V53|Ollama soft dependency: probed at `run` (configured base URL, default `localhost:11434`, `nimble` pulled?); never auto-installed or auto-pulled. `prefilter.mode = auto` (default): shadow when Ollama + `nimble` reachable, else off silently (`doctor` hint `ollama pull nimble`). Shadow scores eligible wakes, never skips, logs score + threshold key + would-skip.
V54|Eligible: checkpoint + turn-end wakes only; never blocked wakes, wakes owing a Debate reply, human promotions.
V55|`skip` only when user set AND fitted `skip_below` exists for (backend, resolved model version, question id + version); else refused (`doctor`) and runs shadow. Skip iff `score < skip_below`. Fail open to wake on timeout, error, oversized input, detected truncation, no threshold, low-confidence `choice`. Skipped wake does not advance cursor; skip logged with input. Fit target: recall ≥0.98 on Concern wakes, 1.0 on Challenge/Escalation wakes. Hosted `prefilter.url` labelled "wake evidence leaves this machine". No trivial-diff gate in v1.

### Host, launch, install (09-choose-host, 10-live-herdr-check, 13-live-idle-delivery, 14-packaging, 19-codex-trust-live-check)
V56|Blocked detection: Claude `PermissionRequest` (incl `AskUserQuestion`) at +0 (not `Notification`). Codex: Herdr OSC `blocked` when present; else `PermissionRequest` with no next hook event (`PreToolUse`/`PostToolUse`/`Stop`) within 10 s, timer cancelled by guardian sibling rollout `task_started`; `task_complete outcome: allow` = tool running; `approvals_reviewer` not trusted. pi: `herdr:blocked` on `pi.events` (dialogs not emitting it = documented gap).
V57|Launcher default: `run -- <harness>` with per-session flags; Codex gets `-c hooks.*` + exactly one inline `-c 'hooks.state={"/<session-flags>/config.toml:<event>:0:0"={trusted_hash="sha256:…"},…}'` covering every session key, hashes from `codex app-server` `hooks/list` `currentHash`. Never dotted form, never second `hooks.state`, never bypass flag.
V58|Hook command string = `~/.pair-watcher/bin/pw-hook <event>` (no version/Cellar path); shim execs current binary else exit 0; hooks pure append, fail-silent; no-op unless a Watcher is registered for the session id; always no-op under the Watcher env guard (Watcher never triggers itself). Launched session: `run` mints session key, registers mailbox `sessions/<key>/`, passes `PAIR_WATCHER_SESSION=<key>` in Worker env; hook routes by that var first, else payload `session_id` (install/attach). Worker session id read from payloads.
V59|`install` opt-in, atomic, idempotent, tagged entries (marker = command under `~/.pair-watcher/` or a `pair-watcher` file name): Claude `hooks` + `env.CLAUDE_CODE_PLUGIN_DIRS` in `$CLAUDE_CONFIG_DIR/settings.json` (default `~/.claude`); Codex entries appended to `~/.codex/hooks.json` + persisted `trusted_hash` for ours only; pi `~/.pi/agent/extensions/pair-watcher.ts`. Manifest records each write. `uninstall` removes only ours, keeps user edits, re-keys shifted user Codex hooks (move unchanged hash to new key), verifies nothing of ours remains.

### Fail-open (20-fail-open, research/spec-process-model-brainstorm)
V86|Failure classes: Service (5xx, 529, 429, network, wake timeout) → retry, cursor holds, `lagging`, never poison guard; Slice (invalid JSONL twice, 400, context overflow, interrupted uncommitted wake once; intentional shutdowns and crashes outside a wake count as nothing) → poison guard; Key (401/403, revoked/expired, billing/quota exhausted) → no retry, BLIND at once; pre-filter down → fail open, ticker once.
V87|Retry per call: 3 attempts, 2 s / 8 s / 30 s + jitter, honour `Retry-After` ≤60 s. Wake wall clock 180 s, blocked 60 s. Lagging re-wake 1 → 2 → 4 → 5 min cap; real triggers wake sooner.
V88|Poison guard: 2 failed wakes (Slice) on same slice → cursor advances, slice recorded as lost coverage + ticker. 2 slices skipped back to back → BLIND.
V89|BLIND triggers: Key class; lagging ≥10 min; 2 back-to-back skipped slices; process or Focus-task crash-loop; transcript lost (hook event but tailer has nothing for that turn within 10 s after one re-anchor rescan); inputs quiet (no hooks + no transcript while repo changes across 2 checkpoints ≥6 min apart); unparseable user config; supervisor gone. Herdr `working` alone never. Swarm: per-Focus BLIND/lagging. Exit on first accepted wake (or next ingested entry for quiet inputs); ticker `blind <from>–<to> (<N> min)`.
V90|Supervisor: no model calls, no Watcher logic. Watcher process heartbeat every 30 s from a thread sharing no locks with wake tasks; silent 90 s → hung. Progress deadline: an outstanding wake with no result 240 s after start (180 s wake clock + 60 s grace) → hung. Hung, or escaped panic/abort/OOM → kill + restart whole process; ≤3 restarts / 10 min per session, then stop + BLIND for all Focuses (`watcher crashed`). Focus task panic caught at task edge (`catch_unwind`): that Focus `BLIND (crashed)`, siblings keep running, no process restart; ≤3 task crashes / 10 min per Focus, then that Focus stays BLIND until `pair-watcher attach` or session end; task crashes never spend the process restart budget; own heartbeat file; dead supervisor → pane shows `BLIND supervisor gone` + notifies (once cap); `attach` re-adopts. Session end: drain one final wake ≤60 s, stop Watchers, exit.
V91|Restart rebuilds from files: pending cursor discarded, committed reloaded, held slice replayed; open Concerns + Debate rebuilt from event log; outbox untouched; Escalation `raised` not `notified` re-checked then notified or `dropped-stale`.
V92|Recovery replay oldest-first from committed cursor as bounded normal-size wakes, each committing; budget exhaustion → `backlog paused`, preserved, not lost. Lost = only actually skipped/unrecoverable activity; replayed = reviewed late. Challenges + Escalations from replayed wakes re-checked against current Worker state before delivery.
